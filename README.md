# 枫子十一

***线上地址：<https://fengzishiyi.github.io/>***

个人写作站。三个领域：**文学**、**哲学**、**计算机科学**。

**纯文本**：没有图片、没有数学公式、没有代码高亮、没有图表。
**非商业**：没有广告、赞助、会员、付费墙、捐赠、推广链接。
**无社交**：没有评论、点赞、分享、关注、注册、推送。
**无追踪**：不加载第三方脚本、不请求外部字体、没有分析代码。

以 Markdown 写作，以 Git 存档，静态生成后托管在 GitHub Pages。

---

## 每天只用三条命令

```bash
npm run dev                        # 边写边看：保存即重建 + 浏览器自动刷新
npm run new                        # 新建一篇（交互式选领域与类型）
npm run verify                     # 提交前：构建 + 14 项端到端检查 + 版式实测
```

`npm run dev` 会同时启动监听与本地服务（<http://127.0.0.1:4321>）。改 `_articles/`、`_site.json`、`src/assets/` 或 `src/*.mjs` 都会触发重建。

**改坏了不影响线上。** 内容或断言不通过时，构建不发布任何文件，终端持续报错直到改好，本地与线上都停在上一版。

## 文章放在哪

```
_articles/
  literature/     文学：诗 小说 散文 随笔 翻译 书信 日记 片段
  philosophy/     哲学：论文 札记 对话 评论 术语 思想实验
  compsci/        计算机科学：技术文章 算法笔记 系统设计 论文笔记 实验 工具 踩坑
```

**目录决定领域，front matter 也必须写一致的 `domain`** —— 两处不一致会直接报错，而不是猜你想要哪个。

跨领域的话题（计算哲学、语言哲学、形式化方法……）用**标签**表达，不新增第四个领域。这样顶层导航永远是三项。

## 一篇文章的 front matter

```yaml
---
title: 标题
slug: why-plain-text           # 可选但建议：决定 URL，发布后不要改
description: 一到三句话        # 必填：元信息块、搜索摘要、悬浮预览都用它
domain: compsci                # 必填，且必须与所在目录一致
kind: 技术文章                  # 必填，且必须属于该 domain
created: 2026-03-10            # 必填 YYYY-MM-DD
modified: 2026-03-12           # 可选，改订日期
status: draft                  # 可选：draft / notes / in-progress / finished / abandoned
tags: [纯文本, 长期主义]        # 可选
series: 个人站点的三次改版       # 可选
confidence: likely             # 可选：high / likely / possible / unlikely / unsure
importance: 4                  # 可选：0–10
license: CC BY-NC-SA 4.0       # 可选，覆盖站点默认
---
```

必填项漏了、`kind` 不属于该领域、`domain` 与目录打架、slug 撞车 —— 都会在构建时报错，并给出「是不是想写 X」的候选。

## 正文支持的几种写法

```markdown
## 小节标题                    会被折成可折叠的一节，并自动生成稳定锚点

行内脚注^[宽屏时排到页边成为边注，窄屏回落到段落下方。]

块级脚注可以写多段：

^^[第一段。

第二段。]

!!! 一句话概括这一段           排在小标题/段落上方，方便跳读

{{ref:why-plain-text}}         引用站内另一篇；构建期校验，拼错给候选
{{ref:why-plain-text|显示文字}} 带自定义链接文字
```

**纯文本站点里，缩进和空行的意义被放大了**：诗和需要保留原样排版的文字请用**四空格缩进**的代码块，那样换行与空格会原样保留。

**写作约定：一句话一行（语义换行）。** 这样 Git 的 diff 是逐句的，能看出改了哪一句，而不是整段重排。

## 命令一览

| 命令 | 作用 |
|---|---|
| `npm run dev` | 监听 + 本地服务 + 自动刷新（日常用这个） |
| `npm run build` | 完整构建并发布到仓库根目录 |
| `npm run new` | 新建文章，交互式选领域与类型 |
| `npm run check` | 风格断言 + 内容检查，不写任何文件 |
| `npm run check:content` | 只检查内容与分类 |
| `npm run check:links` | 列出全部可用 slug、报死链与孤岛文章 |
| `npm run smoke` | 起服务，14 项端到端检查 |
| `npm run layout` | 无头浏览器在 5 个视口下量版式并截图到 `.shots/` |
| `npm run verify` | 构建 + 冒烟 + 版式实测，提交前跑这个 |
| `npm run clean` | 清掉构建产物与截图 |

## 站点结构

```
/                       首页：三个领域入口、最新、随便读一篇、标签
/literature/            领域索引
/philosophy/
/compsci/
/<领域>/<slug>/         文章页
/tags/                  全部标签（自带一段该标签的摘要）
/tags/<标签>/           单标签页
/series/                系列
/archive/               归档：领域 / 类型 / 年份
/search/                全文检索（索引在构建时生成，检索全在浏览器里）
/changelog/             更新
/about/                 自述与许可
/rss.xml  /sitemap.xml
```

旧地址仍然可用：`/articles/`、`/contents/`、`/images/` 会跳转到 `/archive/`，旧的 `/articles/<slug>/` 会跳到该文章的新地址。

## 每篇文章自带的东西

- **元信息块**：领域、类型、始作、改订、状态、把握、重要度、系列、篇幅、修订号
- **目录**：由小节自动生成
- **引用块**：BibTeX / GB/T 7714 / Chicago / Markdown 四种格式，各带一键复制
- **永久链接**：稳定 slug，改标题不会失效
- **修订记录**：从 Git 提交自动生成（`git log --follow`，文件改名也能跟上）
- **反向链接**：谁引用了这一篇，附带那一句上下文
- **本篇引用**：这一篇引用了谁

## 阅读时能调的

文章页滚动后会浮出一条工具栏：字号、行宽、主题（亮/暗/跟随系统）、边注开关。全部记在本地，下次打开还是你选的样子。顶部同时有一条阅读进度线。

**关闭 JavaScript 后**：正文、脚注、目录、标签、互链仍然完整可读 —— 脚本只负责把边注移到页边、加折叠按钮、做悬浮预览和搜索。这条有自动化测试守着（`npm run layout` 会用禁用 JS 的浏览器实测）。

## 设计上值得知道的几条

- **单色**：只有纸色与墨色，加墨色的深浅。颜色只定义在 `src/assets/tokens.css`，别处出现硬编码颜色会被断言拦下。
- **明暗双主题都实测对比度**：正文 16.35:1（亮）/ 13.47:1（暗），次要文字也都过 AA。
- **正文每行 30–34 个汉字**，构建与版式实测两边都守着。这就是为什么正文列宽用 `em` 而不是 `ch` —— 汉字是全角的，一个 `em` 就是一个字，`ch` 只会量到 "0" 的宽度。
- **边注在宽屏排到左侧页边，窄屏回落到段落下方**。它是内联在正文里的 `<aside>`，所以两种情况下都在文档里，也都不需要 JavaScript。
- **动效只作用于导航与索引列表，绝不用在正文** —— 读到一半被动画打断是不可接受的。全部尊重 `prefers-reduced-motion`。

排版手法参考 [gwern.net/design](https://gwern.net/design)（元信息块、边注、语义缩放、双向链接），但中文字距、行宽与边注规则是重新定的。取舍与偏离都记在 `DESIGN-NOTES.md`。

## 上线

构建产物直接落在仓库根目录，GitHub Pages 的 legacy 构建可以直接托管，不需要 CI。

```bash
npm run verify
git add -A && git commit -m "新的一篇"
git push
```

推送后 Pages 会自动重建（约一分钟）。
