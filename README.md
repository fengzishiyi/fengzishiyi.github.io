# 枫子十一 · 一个人的杂志

***线上地址：<https://fengzishiyi.github.io/>***

整站是一本**有期号的杂志**。以文章为唯一单位，图片只作为文章的封面存在。

```
/                 封面 —— 刊名、期号、本期头条
/contents/        目录 —— 按栏目分组
/archive/         往期 —— 按期号倒序
/articles/<标题>/  一篇文章 = 一个杂志跨页
/about/           本刊 + 版本信息
```

---

## 每天只用三条命令

```bash
npm run dev                        # 边写边看，保存即刷新
npm run new -- "文章标题"           # 新建一篇文章（自动填好模板）
npm run verify                     # 提交前跑一遍：构建 + 对比度 + 33 项检查
```

`npm run dev` 会同时启动监听和本地服务（<http://127.0.0.1:4321>）。改 `_articles/`、`_images/`、`_site.json` 或 `src/assets/` 里的任何东西，浏览器会自己刷新。

**改坏了不会影响线上。** 内容检查不通过时构建不发布任何文件，终端会一直显示错误直到改好，本地与线上都停在上一版。

## 写一篇文章

```bash
npm run new -- "标题"
```

它会生成 `_articles/标题.md`，把日期、栏目、封面都填好，并**列出还没被用过的图片**让你直接挑。然后打开改就行：

```yaml
---
title: 为什么这面墙一直在动      # 必填
date: 2026-02-18                # 必填 YYYY-MM-DD
section: 专题                    # 必填：专题 / 作品 / 随笔 / 手记
cover: 99424534-p0              # 必填：_images/ 里文件名的标识形式
kicker: 排版                     # 可选，标题上方的小字
standfirst: 一句话导语。          # 可选，衬线斜体，显示在标题下方
lead: 开篇的导言段。              # 可选，用更大的字号单独排版
summary: 目录与分享卡片用的一句话。  # 可选，不写就取正文第一段
author: 枫子十一                  # 可选，默认取 _site.json
credits: 插画 / 某某              # 可选，署名行
tags: [排版, 动效]                # 可选
feature: true                   # 可选，指定为本期头条
---

正文就是普通的 markdown。

## 小标题

{{figure:137990670-p0|图注，会显示成斜体。}}          ← 栏内插图
{{bleed:135294721-p0|整版出血，铺满视口宽度。}}         ← 出血图
{{quote:一句值得单独排版的话。|出处}}                   ← 跨栏引文，每篇最多 1 条
```

**栏目是固定的四项**，因为目录要靠它分组。写错的栏目名构建会直接报错并列出合法值。想改这四项：`src/build.mjs` 里的 `SECTIONS`。

### 关于封面

**一篇文章一张图。** `cover` 是唯一必填的图片字段，构建会检查它存在。拼错了会报错并**猜你本来想写哪个**。

正文里的 `{{figure:}}` / `{{bleed:}}` 是额外的插图，不是必需的。同一张图可以既是封面又出现在正文里。

竖构图的封面会自动走另一种版式：图片完整显示在上方，文字排在下面的纸面上——因为把一张 0.49 比例的插画裁进横条会毁掉构图，而压在图上又会读不清。

## 加一张图

```bash
copy 新图.jpg _images\
npm run build
```

构建脚本会自己读真实尺寸、按比例分档、生成两档缩略图与占位图。**不需要手填任何尺寸。**

文件名会成为它的标识（`99424534_p0.jpg` → `99424534-p0`）。

想给图片加署名（会显示在大图查看器与文章侧栏里）：

```json
// _images/metadata.json
{
  "99424534-p0": {
    "title": "作品名", "creator": "作者", "year": 2024,
    "medium": "数字绘画", "source": "https://…", "source_label": "来源"
  }
}
```

> **原图不入库。** `.gitignore` 排除了 `_images/`，仓库里只有压缩后的产物。原图请自己另存备份——那个目录丢了就真丢了。

## 期号是怎么来的

**零配置**：年份是卷，月份是期。

```
2026-02-18  →  第 1 卷 · 第 02 期       （卷号 = 年份 − 2026 + 1）
```

首页显示最新一期，归档页按期号倒序。想给某期起名字、加说明、指定头条：

```json
// _issues/2026-02.json
{ "label": "二月刊", "note": "本期主题：排版。", "feature": "why-the-wall-moves" }
```

`_issues/` 整个目录是可选的。文件名叫 `2026-02.json` 或里面写 `"id": "2026-02"` 都行。

想改卷号起点：`_site.json` 里的 `volumeStartYear`。

## 命令一览

| 命令 | 作用 |
|---|---|
| `npm run dev` | 监听 + 本地服务 + 自动刷新（日常就用这个） |
| `npm run build` | 完整构建并发布到仓库根目录 |
| `npm run new -- "标题"` | 新建文章，自动填模板并列出可用图片 |
| `npm run check` | 风格断言 + 内容检查，不写任何文件 |
| `npm run check:content` | 只检查内容（缺封面、栏目写错、slug 拼错） |
| `npm run contrast` | 实测压在图片上的文字对比度 |
| `npm run smoke` | 起服务，逐页逐资源检查 33 项 |
| `npm run shots` | 无头浏览器在 5 个视口下量版式并截图到 `.shots/` |
| `npm run verify` | 构建 + 对比度 + 冒烟，提交前跑这个 |
| `npm run serve` | 只起本地服务 |
| `npm run clean` | 清掉构建产物与截图 |

## 目录结构

```
_site.json        刊名、副题、卷号起点
_articles/        文章 markdown ← 你写的东西
_images/          原图（不入库）+ metadata.json
_issues/          可选的期号信息（可不存在）
src/
  build.mjs       构建与全部断言 —— 唯一会发布文件的地方
  dev.mjs         监听 + 自动刷新
  new.mjs         文章脚手架
  serve.mjs       本地服务（从 .build/ 服务，带自动刷新）
  smoke.mjs       33 项端到端检查
  contrast.mjs    压在图片上的文字对比度实测
  shots.mjs       5 视口量版式 + 截图
  browser.mjs     极简 CDP 客户端（截图与测量共用）
  assets/         手写的 CSS 与 JS（无框架、无 CDN）
contents/ archive/ articles/ about/    构建产物
assets/ images/  index.html  404.html  构建产物
```

## 设计上值得知道的几条

- **纯单色。** 只有暖米色的底 `#F9F8F6` 和柔和的黑 `#1C1C1C`，加上几个预先合成好的灰阶。**页面上所有颜色都来自图片。**
- **冲击力来自尺度、构图与留白**，不来自阴影、渐变或圆角——那些都被风格规则禁止。
- **中文不用负字距。** 衬线标题在拉丁文里收紧字距是惯例，但汉字字面本身密，收紧会伤可读性；所以字号差距承担全部层级。
- **没有网络字体。** 系统衬线（中文回退宋体）配系统无衬线，零字体请求。
- **无障碍是构建期强制的**：对比度、单一 `h1`、跳转链接、地标、被压在图片上的文字对比度，都在断言里。详见 `DESIGN-NOTES.md`。

## 上线

构建产物直接落在仓库根目录，GitHub Pages 的 legacy 构建能直接托管，不需要任何 CI。

```bash
npm run verify
git add -A && git commit -m "新的一期"
git push
```

推送后 Pages 会自动重建（约 1 分钟）。
