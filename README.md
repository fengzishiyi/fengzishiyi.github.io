# 枫子十一

***线上地址：<https://fengzishiyi.github.io/>***

个人写作站。首页是一面砖石网格，每篇文章是一张卡片，站内跳转，没有外链出口。

**纯文本**：没有图片、没有数学公式、没有代码高亮、没有图表。
**非商业**：没有广告、赞助、会员、付费墙、捐赠、推广链接。
**无社交**：没有评论、点赞、分享、关注、注册、推送。
**无追踪**：不加载第三方脚本、不请求外部字体、没有分析代码。

以 Markdown 写作，以 Git 存档，静态生成后托管在 GitHub Pages。
外观照 [chester.how](https://chester.how/) 重做，写作部分的骨架取自 [gwern.net](https://gwern.net/design)。

---

## 每天只用三条命令

```bash
npm run dev                        # 边写边看：保存即重建 + 浏览器自动刷新
npm run new                        # 新建一篇（交互式选领域与类型）
npm run verify                     # 提交前：构建 + 26 项端到端检查 + 六种视口实测
```

`npm run dev` 会同时启动监听与本地服务（<http://127.0.0.1:4321>）。改 `_articles/`、`_reading/`、`_hobbies/`、`_site.json`、`src/assets/` 或 `src/*.mjs` 都会触发重建。

**改坏了不影响线上。** 内容或断言不通过时，构建不发布任何文件，终端持续报错直到改好，本地与线上都停在上一版。

## 内容放在哪

```
_articles/
  literature/     文学：诗 小说 散文 随笔 翻译 书信 日记 片段
  philosophy/     哲学：论文 札记 对话 评论 术语 思想实验
  compsci/        计算机科学：技术文章 算法笔记 系统设计 论文笔记 实验 工具 踩坑

_reading/         阅读：书。status 用 在读 / 已读 / 弃读，可写 author
_hobbies/         爱好：写字之外的事。status 用 当前 / 曾经，可写 note
```

**目录决定领域，front matter 也必须写一致的 `domain`** —— 两处不一致会直接报错，而不是猜你想要哪个。

跨领域的话题（计算哲学、语言哲学、形式化方法……）用**标签**表达，不新增第四个领域。

## 一篇文章的 front matter

```yaml
---
title: 标题
slug: why-plain-text           # 可选但建议：决定 URL，发布后不要改
description: 一到三句话        # 必填：元信息块、搜索摘要、悬浮预览都用它
domain: compsci                # 必填，且必须与所在目录一致
kind: 技术文章                  # 必填，且必须属于该 domain
created: 2026-03-10            # 必填 YYYY-MM-DD
modified: 2026-03-12           # 可选，改订日期
status: draft                  # 可选：draft / notes / in-progress / finished / abandoned
tags: [纯文本, 长期主义]        # 可选
series: 个人站点的三次改版       # 可选
confidence: likely             # 可选：high / likely / possible / unlikely / unsure
importance: 4                  # 可选：0–10
card: wide                     # 可选：给首页那张卡片指定尺寸（intro / wide / square）
pin: 1                         # 可选：数字越小越靠前
license: CC BY-NC-SA 4.0       # 可选，覆盖站点默认
---
```

必填项漏了、`kind` 不属于该领域、`domain` 与目录打架、slug 撞车 —— 都会在构建时报错，并给出「是不是想写 X」的候选。

## 正文支持的几种写法

```markdown
## 小节标题                    折成可折叠的一节，并自动生成稳定锚点

行内脚注^[宽屏时排到页边成为边注，窄屏回落到段落下方。]

块级脚注可以写多段：

^^[第一段。

第二段。]

!!! 一句话概括这一段           段旁概括，用来跳读
!!! note 标题                 带类型的叹号是提示框（note / tip / aside）

+++ 折叠标题                  折叠块，读者点开才展开
+++[标题也可以写在方括号里]

>>> 一句题词                   题词，排在正文之前的引言

::: columns
两栏或多栏并排的内容
:::

正文里的引用 [^md]，配一条定义：
[^md]: 严格说 markdown 也只是众多格式中的一个。

{{ref:why-plain-text}}                引用站内另一篇；构建期校验，拼错给候选
{{ref:why-plain-text|显示文字}}         带自定义链接文字
{{ref:why-plain-text|#sec-2}}          指向那一篇的第 2 节，链接会落在具体章节上
{{ref:why-plain-text|#sec-2|显示文字}}  指向章节并自定义文字
```

指向具体章节的引用会在**被引用的那一节里**长出一条「本节被这些地方引用」，这是 gwern 的 in-context backlink，多数双向链接系统做不到。

**纯文本站点里，缩进和空行的意义被放大了**：诗和需要保留原样排版的文字请用**四空格缩进**的代码块，那样换行与空格会原样保留。

**写作约定：一句话一行（语义换行）。** 这样 Git 的 diff 是逐句的，能看出改了哪一句，而不是整段重排。

## 命令一览

| 命令 | 作用 |
|---|---|
| `npm run dev` | 监听 + 本地服务 + 自动刷新（日常用这个） |
| `npm run build` | 完整构建并发布到仓库根目录 |
| `npm run new` | 新建文章，交互式选领域与类型 |
| `npm run check` | 风格断言 + 内容检查，不写任何文件 |
| `npm run check:content` | 只检查内容与分类 |
| `npm run check:links` | 列出全部可用 slug、报死链与孤岛文章 |
| `npm run smoke` | 起服务，26 项端到端检查 |
| `npm run layout` | 无头浏览器在 6 个视口下量版式、验交互并截图到 `.shots/`（加 `--quick` 只跑交互，几秒） |
| `npm run verify` | 构建 + 冒烟 + 版式实测，提交前跑这个 |
| `npm run clean` | 清掉构建产物与截图 |

## 站点结构

```
/                       首页：一整面砖石网格，第一格是站点自述
/writing/               写作索引
/literature/            领域索引
/philosophy/
/compsci/
/<领域>/<slug>/         文章页
/reading/               阅读：书
/reading/<slug>/
/hobbies/               爱好
/hobbies/<slug>/
/tags/                  全部标签
/tags/<标签>/           单标签页（文章与阅读、爱好混排）
/series/                系列
/archive/               归档：领域 / 类型 / 年份
/search/                全文检索（索引在构建时生成，检索全在浏览器里）
/changelog/             更新
/about/                 自述与许可
/rss.xml  /sitemap.xml
```

导航固定六项：**首页 · 写作 · 阅读 · 爱好 · 标签 · 关于**。这串标签只定义在 `src/templates.mjs` 一处，构建与端到端测试都会逐字比对。

旧地址仍然可用：`/articles/`、`/contents/`、`/images/` 会跳转到 `/archive/`，旧的 `/articles/<slug>/` 会跳到该文章的新地址。

**打错地址不会撞上死胡同。** 404 页面会拿地址里的最后一段和全部 slug 比编辑距离，给出最接近的一篇。
gwern 在服务端做这件事；GitHub Pages 对每个不存在的地址只回同一个静态文件、没有服务端逻辑，所以这一步在浏览器里完成。
**没有 JavaScript 时这一步不会发生** —— 页面仍然给出搜索与归档两条退路，但猜测本身没有了。这是全站唯一一个需要脚本才能工作的功能。

## 每篇文章自带的东西

- **元信息块**：领域、类型、始作、改订、状态、把握、重要度、系列、篇幅、修订号
- **目录**：由小节自动生成
- **引用块**：BibTeX / GB/T 7714 / Chicago / Markdown 四种格式，各带一键复制
- **永久链接**：稳定 slug，改标题不会失效
- **修订记录**：从 Git 提交自动生成（`git log --follow`，文件改名也能跟上）
- **反向链接**：谁引用了这一篇，附带那一句上下文
- **节级反向链接**：谁引用了**这一节**，直接长在那一节里面
- **本篇引用**：这一篇引用了谁
- **相关**：共用标签（按稀有度加权）与同系列的篇目，每条都写明理由
- **链接预览**：悬停或键盘聚焦站内互链，浮出目标那一篇的标题、元信息与摘要 —— 片段是构建期生成的，不发出任何请求

另外两处不在文章页里：**搜索**（索引构建期生成，检索全在浏览器里）、**404 猜测**（打错地址时给出最接近的一篇，见下）。

## 首页那张网格

断点与 chester.how 一致：手机 1 栏、≥640px 2 栏、≥1024px 3 栏、≥1280px 4 栏。

卡片有三种尺寸：**intro**（第一格，站点自述，大方块）、**wide**（2:1 横条）、**square**。第一格永远是 intro；其余按内容定，也可以在 front matter 里用 `card:` 指定。默认由类型决定 —— 诗和片段短，用小格；书与爱好是方块。

每张卡片的右上角是一个细描边的 `↗`，它是装饰而不是第二个链接 —— 整卡可点由标题链接上的一层覆盖实现。收藏夹的卡片带一个状态胶囊（在读 / 已读 / 当前……），文章卡片不带标签，跟参考站一致：标签在文章页与 `/tags/` 里。

卡片整体可点，但**不是**把整张卡包进一个 `<a>`：标题是链接、图片区是链接，「铺满整张卡」由一层 `::after` 覆盖层实现。嵌套 `<a>` 会被浏览器拆掉外层标签，那张卡片就会悄悄退化成一个普通方块 —— 构建期与端到端测试都会拦这个。

## 阅读时能调的

只剩一个按钮：**阅读模式**。打开后右栏让位、正文占满、行宽略放宽，状态记在本地，下次打开还是你选的样子。

**没有暗色模式，没有字号/行宽切换，也没有阅读进度线。** 这一版照 chester.how 的外观重做，那些控件被明确去掉了（理由见 `DESIGN-NOTES.md`）。

**关闭 JavaScript 后**：正文、脚注、目录、标签、互链、五种块级写法仍然完整可读 —— 脚本只负责把边注移到页边、加折叠按钮、做悬浮预览和搜索。这条有自动化测试守着（`npm run layout` 会用禁用 JS 的浏览器实测）。

## 设计上值得知道的几条

- **颜色只有一套亮色**：纸白、卡片灰、墨黑，加上琥珀/天蓝等标签底色。全部定义在 `src/assets/tokens.css`，别处出现硬编码颜色会被断言拦下。
- **对比度实测**：正文 21.0:1、卡片正文 9.9:1、次要文字 4.3:1，都过 AA。
- **字体走系统栈**，不下载任何字体。chester 是 Fraunces 排标题、Inter 排正文，这里换成系统衬线栈排标题（中文落到宋体一类）、系统无衬线栈排正文 —— 衬线／无衬线的对比保留，字形由读者的机器决定。字号、字重、字距照 chester 逐项抄下来（标题 300 字重、`−1.08px` 字距、正文 16px/26px、`−0.40px`）。这是刻意的取舍，不是没做完。
- **正文每行 30–34 个汉字**，构建与版式实测两边都守着。这就是为什么正文列宽用 `em` 而不是 `ch` —— 汉字是全角的，一个 `em` 就是一个字，`ch` 只会量到 "0" 的宽度。
- **边注在宽屏排到左侧页边，窄屏回落到段落下方**。它是内联在正文里的 `<aside>`，所以两种情况下都在文档里，也都不需要 JavaScript。
- **动效只作用于导航与索引列表，绝不用在正文** —— 读到一半被动画打断是不可接受的。全部尊重 `prefers-reduced-motion`。

写作骨架参考 [gwern.net/design](https://gwern.net/design)（元信息块、边注、语义缩放、双向链接、节级反向链接），中文字距、行宽与边注规则是重新定的；视觉皮肤参考 chester.how。取舍与偏离都记在 `DESIGN-NOTES.md`。

## 上线

构建产物直接落在仓库根目录，GitHub Pages 的 legacy 构建可以直接托管，不需要 CI。

```bash
npm run verify
git add -A && git commit -m "新的一篇"
git push
```

推送后 Pages 会自动重建（约一分钟）。
